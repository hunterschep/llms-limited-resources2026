# WMT26 Rules Summary

Sources:

- Official task page: https://www2.statmt.org/wmt26/limited-resources-llm.html
- Official repository: https://github.com/TUM-NLP/llms-limited-resources2026
- ACL call: https://www.aclweb.org/portal/content/wmt-2026-shared-task-multitask-llms-limited-resources

The official page was last checked from this repository setup on 2026-05-21. The page states it was last updated on 2026-05-08; the ACL call was posted on 2026-05-18.

## Hard Constraints

WMT26 has two leaderboards:

- Ukrainian track: `uk`
- Sorbian languages track: `hsb` and `dsb`

For each submitted track, the system must cover all five tasks:

- MT: Machine Translation
- QA: Multiple-choice Question Answering
- SC: Spell Checking
- GC: Grammar Checking
- MR: Maths Reasoning

Submissions that cover only one task, such as MT-only or QA-only, do not count for the leaderboard. For a given track, MT, QA, SC, GC, and MR outputs must be generated by the same model. Task-specific prompts are allowed; inference-time adapter switching, hidden ensembles, or live RAG dependencies are not part of our compliant design.

Allowed model family:

- Qwen3.5 family
- 2B parameters or smaller
- `Qwen/Qwen3.5-2B`
- Quantized Qwen3.5 variants at <=2B
- Unsloth Qwen3.5 variants at <=2B

Model submission expectation:

- Submit the model itself for hidden evaluation.
- Public Hugging Face upload is recommended when possible.
- Private submission to organizers is available; they state they will not publish private models.

## Data Releases

The local official repository includes:

- Ukrainian MT dev sets for en-ukr and cs-ukr.
- Ukrainian QA train/dev for ZNO and Ukrainian MMLU.
- Ukrainian SC/GC/MR dev files.
- Sorbian MT train/dev data for de-hsb, de-dsb, and hsb-dsb.
- Sorbian hsb/dsb monolingual support corpora.
- Sorbian QA/SC/GC/MR dev files.

The release is asymmetric. Not every task has official train data. `*_dev.jsonl` files are treated as official development data for prompt inspection, tuning, and locked validation unless a final policy explicitly overrides that.

## Evaluation

Per-task metrics:

- MT: chrF++; BLEU is also reported.
- QA: accuracy.
- MR: accuracy.
- SC: F1 for detection and F1 for correction.
- GC: F1 for detection and F1 for correction.

Internal scoring convention:

```text
MT_score = average chrF++ over required directions
QA_score = accuracy * 100
SC_score = mean(detection_F1, correction_F1) * 100
GC_score = mean(detection_F1, correction_F1) * 100
MR_score = accuracy * 100
overall_score = mean(MT_score, QA_score, SC_score, GC_score, MR_score)
```

The official final leaderboard considers all five tasks equally. This makes negative transfer central: optimizing MT while damaging QA, MR, SC, or GC is strategically bad.

## External Data Policy

External data is allowed only when publicly available for fairness and reproducibility. Every external, synthetic, teacher-generated, translated, or distilled source must be registered in `data/manifests/data_governance_registry.csv` before use.

Forbidden or contamination-risk data:

- Hidden test data.
- WMT2025 test sets.
- UNLP2024 Ukrainian QA test splits.
- Ukrainian MMLU test splits.
- Original PolyMath.
- Translated PolyMath.
- Modified PolyMath.
- PolyMath-derived synthetic data.
- Extra Sorbian language certificate questions beyond official provided material.
- Private or unlicensed data.
- Data whose public source cannot be documented.

## Important Dates

The official page/call lists the 2026 shared-task schedule in broad terms:

- Test data release expected at the end of June 2026, with one page giving 2026-06-29.
- System submission expected in July 2026.
- System paper period follows the shared-task submission.

Dates should be rechecked before launch because shared-task schedules can move.

## Open Questions For Organizers

- Exact required hidden-evaluation packaging format for model artifacts and tokenizer/config files.
- Whether any inference-time preprocessing wrappers are allowed beyond ordinary prompting.
- Whether final training may include official dev examples after method selection, and how that should be reported.
- Whether quantized/Unsloth variants must preserve exact architecture metadata for submission.
- Whether official evaluator scoring uses exactly the same SC/GC parsing assumptions as this repo’s wrapper.
